    5. **handleLookup** (L-05 flow, RESEARCH Q2 + Q10):
       ```ts
       async function handleLookup(e: React.FormEvent) {
         e.preventDefault();
         setForm(f => ({ ...f, errorKind: null }));
         const trimmed = form.lookupName.trim();
         if (!trimmed) {
           setForm(f => ({ ...f, errorKind: "validation" }));
           return;
         }
         setIsSearching(true);
         try {
           const res = await fetch("/api/rsvp/lookup", {
             method: "POST",
             headers: { "Content-Type": "application/json" },
             body: JSON.stringify({ name: trimmed }),
           });
           if (res.status >= 500) {
             setForm(f => ({ ...f, errorKind: "server" }));
             return;
           }
           if (!res.ok) {
             setForm(f => ({ ...f, errorKind: "validation" }));
             return;
           }
           const data: { found: boolean; household_id?: string; members?: { guest_id: string; full_name: string }[] } = await res.json();
           if (!data.found) {
             setForm(f => ({ ...f, errorKind: "miss" }));
             return;
           }
           const members = data.members ?? [];
           // Atomic setForm — sets stage + household + submissions in ONE call to avoid an intermediate render (RESEARCH Q10, Pitfall 3).
           setForm({
             stage: "form",
             lookupName: trimmed,
             household: { id: data.household_id!, members },
             submissions: members.map(m => ({
               guest_id: m.guest_id,
               full_name: m.full_name,
               attending: null,
               meal_choice: null,
               dietary_restrictions: "",
             })),
             errorKind: null,
           });
         } catch {
           setForm(f => ({ ...f, errorKind: "network" }));
         } finally {
           setIsSearching(false);
         }
       }
       ```

<risks_notes>
## Risks and explicit deviations

- **Deviation from CONTEXT Discretion: motion vocabulary.** CONTEXT line 85 suggests `reveal-on-scroll` for form-stage member rows. RESEARCH Q6 (verified against `app/globals.css` lines 433-436) proves `reveal-on-scroll` uses `animation-timeline: view()` — a scroll-driven CSS spec that does NOT fire on elements that mount already-in-viewport. Form-stage rows mount inside the visible form card on stage transition; they would render at `opacity: 0` and stay invisible. Plan 05-01 preempts this by omitting `reveal-on-scroll` everywhere in the page; Plan 05-02 uses an inline `animation` style referencing the existing `hero-fade-up` keyframe (`globals.css` line 335) with a per-row stagger delay. Both motion paths respect `prefers-reduced-motion` automatically via `globals.css` line 613.
- **Deviation note: `attending` UI representation.** D-02 locks `attending: "yes" | "no" | null` in the FormState. Phase 4's submit endpoint (`app/(main)/api/rsvp/submit/route.ts`) expects `attending: boolean` in the request body. Phase 5 commits the string-union UI shape now; Phase 6 transforms `"yes" → true`, `"no" → false` inside its submit handler before POSTing. This boundary is documented in the file header comment of `rsvp/page.tsx` so the Phase 6 implementer sees it on file open.
- **No hydration workaround for `autoFocus`.** RESEARCH Q4 verified against the React 19.2.4 source (`react-dom-client.development.js:22158`, `react-dom-server.node.development.js:1415`) that `autoFocus` is serialized to HTML during SSR and React reconciles cleanly during hydration. No useEffect-ref dance, no `suppressHydrationWarning`, no `useId` workaround. If a future React/Next.js upgrade flags this, revisit; for now, the simple `<input autoFocus />` is correct.
- **Pitfall 4 (aria-live announcement on every render):** Defended via Option A from RESEARCH Pitfall 5 — the banner `<div>` (with `role="alert"` + `aria-live="assertive"`) is conditionally rendered, not just its inner content. SR announces only when the banner mounts.
- **Pitfall 5 (miss-palette / error-palette swap):** Defended via Option A — two separate conditional renders, one per palette family. There is no class-string interpolation that could accidentally inherit a destructive token in the miss banner.
- **Plan 05-01 leaves the form-stage placeholder render in place** so the focus effect target (`formHeadingRef`) attaches to a real DOM node and the lookup smoke can prove stage transition end-to-end. Plan 05-02's first task is to replace the placeholder paragraph (`Plan 05-02 renders N member row(s) here.`) with the full `submissions.map(...)` member rows + the disabled submit button.
