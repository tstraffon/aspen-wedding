<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Card anchor click -> external registry site | Registry destinations are third-party (Honeyfund, Amazon, Crate & Barrel). The new-tab navigation crosses the trust boundary from `aspen-wedding.com` (in production) to the external domain. The risk is reverse-tabnabbing: a malicious or compromised destination could call `window.opener.location = "..."` and redirect the parent tab if `rel="noopener"` is absent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering (reverse-tabnabbing, CWE-1022, OWASP A05) | Three card `<a>` tags in `/registry` page grid | mitigate | Every card anchor carries `target="_blank" rel="noopener noreferrer"`. Verified by acceptance criterion on Task 2 (`grep -c 'rel="noopener noreferrer"'` is 1, inside a map of 3 — every rendered anchor inherits). `noopener` severs `window.opener`; `noreferrer` additionally strips the `Referer` header so destination sites cannot fingerprint inbound traffic. Both are mandatory per the planning-context security_context block (HIGH severity, ASVS L1). |
| T-02-02 | Information Disclosure (referrer leak to third parties) | Three card `<a>` tags | mitigate | `rel="noreferrer"` (included alongside `noopener`) prevents `Referer` header from leaking. Acceptable because guests are willingly clicking the link — but defense-in-depth applies. |
| T-02-XSS | Tampering / XSS via React props | Hardcoded `registries` array values rendered through JSX | accept | `title`, `description`, `alt`, `link` are all string literals from the module source — no user input, no `dangerouslySetInnerHTML`. React's text-node escaping covers ASVS L1 §5.3. Risk is zero pending a future move to user-editable registry data. |
| T-02-PLACEHOLDER | Information Disclosure (shipping `#` URLs to production) | Card `link` fields | accept (transferred to handoff) | D-12 explicitly defers real URLs to Tyler at handoff. The `// TODO: replace with real registry URL` comments (verified by acceptance criterion) keep the gap visible at code-review time. Not a security vulnerability in the technical sense, but flagged because broken placeholder links would surface as a UAT defect. |
</threat_model>
