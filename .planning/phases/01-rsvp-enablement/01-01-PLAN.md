<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> /api/rsvp | Untrusted form payload crosses here; client validation can be bypassed |
| /api/rsvp -> Supabase PostgREST | Anon-key authenticated insert; RLS is the authorization gate |
| Public web -> Supabase rsvps table | RLS write-only policy is the boundary; no SELECT exposure |
| Repo contributors -> env files | `.env.local` must never be committed; `.env.local.example` documents the contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SR | Spoofing | API route service-role fallback (line 17) | mitigate | Drop `SUPABASE_SERVICE_ROLE_KEY ??` from line 17 — anon-only ensures RLS policy is exercised. Prevents accidental privilege escalation if a contributor sets the env var. (Task 4) |
| T-01-IL | Information leakage | Raw `error.message` echoed in 500 response (line 40) | mitigate | Replace with generic "Could not save RSVP" + server-side `console.error`. PostgREST errors can leak schema details. (Task 4) |
| T-01-TI | Tampering | Anon role inserts arbitrary rows | accept | Wedding context; low-value target; RLS WITH CHECK (true) is sufficient. Spam mitigation deferred (out of phase scope — could add rate limit or honeypot later). |
| T-01-EP | Elevation of Privilege | Anon role reading existing RSVPs | mitigate | Write-only RLS policy: INSERT with `TO anon`, NO SELECT policy for anon. Verified in Task 3. |
| T-01-EX | Information disclosure | `.env.local` committed to git | mitigate | `.gitignore` already excludes `.env*`; Task 5 adds `!.env.local.example` negation to allow the example through without the live file. |
| T-01-SC | Tampering | npm/pip/cargo installs | N/A | No new packages installed in this plan. Existing `@supabase/supabase-js` was vetted at project setup. |

Note on T-01-TI: a malicious actor can submit unlimited RSVPs with fake names. For a wedding site with <200 expected guests, the user can manually clean garbage rows from Supabase Studio. If spam becomes a real problem post-launch, add a hCaptcha or Turnstile widget in a follow-on phase.
</threat_model>
