<objective>
Ship a new POST endpoint at `/api/rsvp/lookup` that gates the v0.2 RSVP flow: a guest types their name on Phase 5's lookup screen, the endpoint matches it against `public.guests` with a case-insensitive trim comparison (D-09), and on hit returns the full household so Phase 6's group form can render every member's row (D-11). On miss, HTTP 200 with `{found: false}` — miss is a business outcome, not an error.

Purpose: This is the read-side half of the v0.2 API contract. Phase 5's UI calls it; the response shape is locked here. The route does NOT modify `app/(main)/api/rsvp/route.ts` v0.1 (D-16 — Phase 5 swaps the form away from v0.1; deletion is Phase 5+'s call). All Phase-1 hardening patterns (anon-only client, module-call-time env reads with sanitized 500, sanitized 5xx with no PostgREST leakage) are carried forward verbatim per the shared patterns in 04-PATTERNS.md.

Output:
- `app/(main)/api/rsvp/lookup/route.ts` (new) — Next.js 16 Route Handler exporting `POST(request: NextRequest)`. Two-query flow: case-insensitive trim match → on hit, household fetch by household_id.

Verification is curl-based smoke tests against `npm run dev`, matching Phase 3's VALIDATION posture (no test framework installed per CONTEXT Claude's Discretion). The dev seed from Plan 04-01 provides the fixture data (Tyler+Emily in household `1111...`, Sarah Else in `2222...`, Sarah Horan in `3333...`).
</objective>
