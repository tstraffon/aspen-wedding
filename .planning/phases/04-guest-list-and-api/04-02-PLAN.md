<objective>
Ship a new POST endpoint at `/api/rsvp/lookup` that gates the v0.2 RSVP flow: a guest types their name on Phase 5's lookup screen, the endpoint matches it against `public.guests` via the `lookup_guest_by_name(p_name)` SQL function (created in Plan 04-01 per the W-2 fix), and on hit returns the full household so Phase 6's group form can render every member's row (D-11). On miss, HTTP 200 with `{found: false}` — miss is a business outcome, not an error.

The route does NOT modify `app/(main)/api/rsvp/route.ts` v0.1 (D-16 — Phase 5 swaps the form away from v0.1; deletion is Phase 5+'s call). All Phase-1 hardening patterns (anon-only client, module-call-time env reads with sanitized 500, sanitized 5xx with no PostgREST leakage) are carried forward verbatim per the shared patterns in 04-PATTERNS.md.
